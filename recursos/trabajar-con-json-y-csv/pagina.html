JSON y CSV son los dos formatos con los que se mueven casi todos los datos entre programas. El JSON lo entregan las API y lo esperan las aplicaciones web; el CSV es lo que exportan y abren las hojas de cálculo. Cuando algo falla, el mensaje de error rara vez ayuda: un carácter de más, un separador equivocado, un cero que desaparece. Las cuatro herramientas de esta guía están pensadas para localizar esos fallos y para convertir entre ambos formatos sin alterar los datos. Todo ocurre en tu navegador, de modo que puedes usarlas con información privada.

Cuando el JSON no se lee: valida primero

Si una aplicación rechaza un JSON, empieza con Validador JSON. Comprueba la sintaxis estricta del estándar y te dice la línea y la columna del primer problema, con una flecha sobre el punto exacto. La columna a veces cae algo después del fallo real, así que mira también el carácter anterior. Los errores más frecuentes son siempre los mismos:

  • Una coma tras el último elemento de un objeto o lista.
  • Comillas simples en lugar de dobles, o claves sin comillas.
  • Comentarios, que el estándar no admite aunque algunos programas los toleren.
  • Valores que no existen en JSON, como undefined o NaN.
  • Ceros a la izquierda en un número, como 007.

Si el JSON es válido, te da un resumen de su estructura: tipo del valor principal, número de objetos, listas y claves, y niveles de anidamiento. Ten claro qué no comprueba: no sabe si falta un campo que tu aplicación necesita ni si un valor tiene el formato correcto.

Para leerlo o enviarlo: formatea o minifica

Formateador JSON tiene dos modos. Embellecer deja cada clave en su línea, con la sangría que elijas, para leer, revisar y comparar. Minificar quita todos los espacios para enviarlo por red o incrustarlo. Lo que lo distingue es que no reescribe tus datos: un entero largo o un 1.50 se copian tal como están, y solo cambian los espacios, algo que no hacen todos los formateadores. Si ordenas las claves a todos los niveles, comparar dos documentos resulta mucho más fácil. Avisa de las claves repetidas, casi siempre un error.

De JSON a una hoja de cálculo

Conversor JSON a CSV convierte una lista de objetos en una tabla, con una columna por clave y una fila por objeto. Los objetos anidados se aplanan con un punto, por ejemplo direccion.ciudad, y las listas internas se escriben como JSON en una celda para no perder información. Hay un detalle de Excel en español que causa muchas consultas: si al abrir el archivo todo aparece en una sola columna, genera de nuevo el CSV con punto y coma, que es el separador habitual. Para que los acentos y la eñe se vean bien, usa la descarga pensada para Excel. Si los datos vienen de una fuente que no controlas, activa la casilla de neutralizar fórmulas, porque una celda que empieza por un signo igual podría ejecutarse al abrir la hoja.

De una hoja de cálculo a JSON

Conversor CSV a JSON detecta si el archivo usa comas, puntos y comas, tabuladores o barras verticales, y respeta las comillas y los saltos de línea dentro de un campo. Lo cuidadoso está en los números: «007» se queda como texto para no perder ceros, y un entero de más de 15 cifras, como un identificador, también, porque el redondeo de JavaScript lo estropearía. Con decimales con coma, la opción adecuada convierte «3,14» en 3.14. Si una fila tiene más o menos celdas que la cabecera, la herramienta te avisa y rellena o nombra las que faltan o sobran.

Un flujo típico

  1. Recibes datos de una API: valídalos y formatéalos para entenderlos.
  2. Conviértelos a CSV para que otra persona los revise en una hoja de cálculo.
  3. Cuando vuelvan corregidos, pasa el CSV a JSON y vuelve a validar el resultado.
  4. Minifica la versión final antes de enviarla o incrustarla.
